## 2. Befunde

- **P3 – `==` vergleicht Bits, `<`/`>`/`<=`/`>=` nach Pascal; Pascal-`=` hat keinen Operator**
  ([Real48.cs#L338](https://github.com/kaaasi/bomb-redone/blob/c341c5623d35bb03fa677ddb8f9200c093bfe472/src/BombRedone.Core/Numerics/Real48.cs#L338)).
  Beleg: `real48.py eval cmp 001234567800 000000000000` → `result 00` (gleich), im Remake ist
  `FromHex("001234567800") == Real48.Zero` aber `false`, während `<=` und `>=` beide `true` liefern. Dokumentiert (XML-Doku,
  `real48.md` „Cmp“), aber eine Falle für die Spuren, die Pascal-`=`/`<>` übernehmen. Vorschlag: Hinweis in den
  Anforderungen der Folgespuren („Pascal-`=` ist `Compare(a, b) == 0`“) oder eigene Methode `PascalEquals`. Kein Fix in
  dieser Spur nötig.

**Gegenprüfung ohne Befund:**

- **Einsprünge und Fehlercodes** (`12CE:11B6–11FF`): Add/Sub `jc 11F6` (AX = CDh = 205), Div `or cl,cl; jz 11FC`
  (C8h = 200) vor `107A`, Trunc/Round `mov ch,0/1; call 115A; jc 11F0` (CFh = 207), Sqr kopiert DX:BX:AX nach CX:SI:DI –
  wie im Code. Dateioffsets: Header 0x16A0 + `12CE0h` = `0x14380`, Fundstellen in den `[ORIGINAL]`-Kommentaren stimmen.
- **LongInt → Real (`111B`), Trunc/Round (`115A`)** Zeile für Zeile gelesen: Betrag, Wort-/Byteschiebung A0h/90h/88h,
  AH = 0; Exponent > 9Fh → 207 (also −2³¹), Exponent < 80h → 0, Wort- und Byteschritte vor dem letzten Bitschritt (das
  Halbbit kommt immer aus dem letzten `rcr`), `js` nach dem Aufrunden → 207. Remake identisch, auch `shift == 32`.
- **Zufall**: `16C4` = `RandSeed × 08088405h + 1` (Faktor-Low `8405h` bei `16FA`, `0808h` über die Schiebungen);
  `1675` = oberes Wort mod n, 0 für n = 0; `168B` = Exponent 80h, 32 Schritte, sonst AL = 0, AH = 0, `and dh,7Fh`;
  `16FC`: `mov ah,2Ch; int 21h; mov [3AD6],cx; mov [3AD8],dx` → CX ins untere Wort. Korrektur in `FromClock` belegt.
- **Mul-Kurzweg (`0FAC`)**: `mov al,ah; mul ch` nimmt nur das obere Byte von BP mal CH; Fall `9A000000DE2B × 61CFBABB9333`
  per Hand: exakt `788F 6882 9444`, Original `788F 6882 9391`, nach Normalisieren und Runden AH 27h statt 29h – Probe
  `7A2705D11E71`, Remake gleich. Die in `real48.md` genannten Mul-Abweichungen sind also Originalverhalten (höchstens 2 ulp).
- **Probe-Hashes gleichlaufend und abgesichert**: `real48.py hashes --count 20000` liefert alle elf Werte aus
  `Real48ProbeTests`/`TurboPascalRandomTests` exakt; eine Änderung am C#-Generator (M12) macht die Tests rot. Die Tests brauchen
  keine Originaldaten (feste Hashes), laufen also auch in der CI.
